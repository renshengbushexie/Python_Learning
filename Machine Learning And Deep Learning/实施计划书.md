## 三、每文件完善标准

### 3.1 参考资料章节改造

**改造前（现状）：**
```markdown
## 参考资料
- [Legacy Source: readme_learning01.md](../../../归档/readme_learning01.md)
```

**改造后（目标）：**
```markdown
## 参考资料

### 原始论文
- Author et al. "Paper Title." Conference/Journal, Year.

### 教材参考
- [d2l §X.X 章节名](https://zh.d2l.ai/chapter_xxx/xxx.html)
- [Bishop, 2006] §X.X — 对应内容说明
- [Goodfellow et al., 2016] §X.X — 对应内容说明

### 扩展阅读
- 综述论文、实现文档、官方教程等
```

### 3.2 数学推导增强标准

| 要求 | 说明 |
|------|------|
| 公式来源标注 | 关键公式旁标注出处，如 `（参见 [Bishop, 2006] 式3.15）` |
| 推导完整性 | 关键步骤不跳步，中间变量有解释 |
| 符号一致性 | 同一文件内符号定义不冲突 |
| 定理引用 | 涉及的数学定理/引理需标明名称与来源 |

### 3.3 内容深度标准

| 章节 | 最低要求 |
|------|----------|
| 模型实现原理 | ≥3 个核心公式，完整推导链，标注来源 |
| 主要优点 | 每条有理论依据或实验数据支撑 |
| 主要缺点 | 每条对应具体的理论局限性 |
| 解决办法 | 引用解决方案的出处论文/方法 |
| 参考资料 | ≥1 篇原始论文 + ≥1 本教材章节 |

## 五、执行原则

### 5.1 学术诚信原则

| 原则 | 要求 |
|------|------|
| **不凭空捏造** | 所有数学公式必须可追溯至原始论文或权威教材 |
| **标注来源** | 关键公式旁标注出处 |
| **如实引用** | 论文作者、标题、年份、会议/期刊必须准确 |
| **区分原创与引用** | 个人总结性文字与引用内容界限清晰 |

### 5.2 内容质量原则

| 原则 | 要求 |
|------|------|
| **理论深度** | 推导过程应展示核心思想，而非机械罗列公式 |
| **实用导向** | 参数说明和选型建议需有实际经验支撑 |
| **对比思维** | 优缺点分析应与同类算法横向对比 |
| **与时俱进** | 引用最新的综述和改进工作（如适用） |

### 5.3 一致性原则

| 原则 | 要求 |
|------|------|
| **格式统一** | 所有文件遵循相同的 LaTeX 排版规范 |
| **术语统一** | 同一概念在不同文件中使用相同术语（参照 glossary.md） |
| **符号统一** | 向量用粗体小写 $\mathbf{x}$，矩阵用粗体大写 $\mathbf{X}$，标量用普通字体 |

## 六、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 某些前沿算法缺乏权威教材覆盖 | 参考来源有限 | 以原始论文 + 高引综述为主要来源 |
| d2l.ai 未覆盖的算法较多 | 无法统一对照 | 按算法领域选用对应权威教材 |
| 部分算法的数学推导极其复杂 | 完整推导篇幅过长 | 保留核心推导，复杂步骤指引至原始论文 |
| 文件数量大（400+），一致性维护困难 | 格式/术语可能不统一 | 分批执行，每批完成后做一致性检查 |
